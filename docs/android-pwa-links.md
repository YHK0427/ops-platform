# assetlinks.json — 안드로이드에서 링크를 PWA 로 여는 설정

## 이게 왜 있나
안드로이드에 설치한 PWA(WebAPK)는 이 사이트 주소에 대한 intent filter 를 이미 갖고
있다. 그런데 Android 12 부터는 **사이트가 "그 앱이 내 앱이 맞다"고 보증해주지 않으면**
그 앱을 무시하고 조용히 기본 브라우저로 열어버린다. 선택 대화상자도 안 뜬다.
이 파일이 그 보증이다. 있으면 기수원이 아무 설정도 하지 않아도 링크가 PWA 로 열린다.

## 값의 출처
- `package_name`: 크롬 주소창에 `chrome://webapks` → UnivPT 항목의 Package name.
  사람마다 다르지 않다. Chromium 소스상 이 이름은 구글의 발급 서버가 정해서 내려주고
  (`WebApkResponse.package_name`), 그 요청에는 사용자·기기 식별자가 전혀 실리지
  않는다(쿠키도 끈다). 크롬 코드에도 "다른 크롬 버전이 이미 설치했을 수 있다"며
  같은 이름을 기대하는 검사가 있다.
- `sha256_cert_fingerprints`: 구글이 WebAPK 를 서명하는 인증서의 지문.
  Chromium 소스의 `ChromeWebApkHostSignature.EXPECTED_SIGNATURE` 바이트 배열을
  그대로 디코드해 계산했다. 인증서 주체는 `C=US, O=Google, OU=Chrome WebAPK, CN=CA`,
  유효기간 2016-08-23 ~ 2044-01-10.

## 건드리면 안 되는 것
`manifest.webmanifest` 의 **주소**나 **id** 를 바꾸면 안드로이드가 다른 앱으로 보고
패키지 이름이 바뀐다. 그러면 이 파일도 같이 고쳐야 한다.
아이콘·이름·테마색·scope 변경은 패키지 이름을 바꾸지 않는다.

## 확인 방법
안드로이드에서 설정 → 앱 → UnivPT → 기본으로 열기.
"확인된 링크"로 잡혀 있으면 성공. 재설치하거나 기기를 재부팅하면 다시 검증한다.

주의: 검증은 **앱 설치·업데이트 시점**에 일어난다. 이미 설치한 사람은 바로 반영되지
않을 수 있고, WebAPK 가 업데이트될 때(보통 며칠 주기) 또는 재설치하면 적용된다.
